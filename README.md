# telugu-purana-rag

Code for the Purana agent: GRETIL parsing, chapter-card generation (direct + Batch API), in-memory retrieval,
the LangGraph agent, the Hugging Face Space, and the evaluation harness. Data (corpus, cards, index) is not in this
repo — it lives in the private HF dataset `amrithatejaswiservices/telugu-purana-index`. Write-up:
https://aiengineeringnotes.com/articles/telugu-purana-rag/

The **Purana agent** of the Telugu dharma-sandehalu app. One agent for all Puranas and
Itihasa (moral / story questions); the Bhagavad Gita agent (`~/telugu-rag`) stays separate.

## Design: index the questions, not the verses

The Sanskrit is the corpus; there is no open-licensed Telugu prose for the Puranas and we do not
bulk-translate. Instead every adhyaya gets one Telugu **chapter card**, generated once, offline:

- `summary_te`, `key_events_te`, `moral_te` - what happens and what it teaches
- `questions_te` - 8-12 questions a devotee would ask that this chapter answers (the primary retrieval surface)
- `entities` - Telugu name + canonical IAST stem + kind (gazetteer input)
- `anchors` - key events mapped to exact verse ids (citation support)

Retrieval is coarse-to-fine: Purana profile -> chapter card (dense over questions/summary + char-4gram BM25,
RRF fused) -> the chapter's Sanskrit verses go to the answering model, which quotes verse ids and writes
the Telugu meaning. Translations are written back to `tatparyam_te` lazily as `unreviewed`.

## Layout

| Path | What |
|---|---|
| `sources/gretil/` | raw GRETIL downloads, never edited |
| `corpus/<work>.jsonl` | one record per verse: IAST, Telugu script, Devanagari, citation, licence, empty `tatparyam_te` |
| `corpus/<work>_adhyayas.jsonl` | adhyaya manifest (verse ids, speakers) |
| `corpus/sources.json` | provenance, rights, checksums |
| `cards/<work>/<adhyaya_id>.json` | generated chapter cards + usage/cost + `review_status` |
| `eval/gold_*.jsonl` | Telugu gold questions with gold adhyaya ids |
| `scripts/build_gretil_purana.py` | GRETIL plaintext -> verse records |
| `scripts/gen_cards.py` | chapter cards via Claude Opus 5 (structured output), idempotent, parallel |
| `scripts/eval_cards_retrieval.py` | adhyaya-level hit@k / MRR over cards |

## Licence flag

GRETIL e-texts are **CC BY-NC-SA 4.0 (non-commercial)**. The Sanskrit itself is public domain, but the
digitisation licence binds redistribution. Before any commercial release, re-source the same texts from
Ambuda / Sanskrit Wikisource and re-run the parser; verse ids are edition-based and will survive.

## Purana agent (`app/`)

Run with the Gita project's venv, which has LangGraph, Qdrant, sentence-transformers and rank_bm25:

```bash
~/telugu-rag/.venv/bin/python app/build_index.py          # once; ~90 min on CPU (embeddings cached in work/embcache.pkl)
set -a; source ~/telugu-rag/.env; set +a
~/telugu-rag/.venv/bin/python app/ask.py "ధ్రువుడు ఎందుకు తపస్సు చేశాడు?"
~/telugu-rag/.venv/bin/python app/ask.py "dhruvudu enduku tapassu chesadu?" --json
```

Graph (`app/graph.py`), same contract as `telugu-rag/app/graph.py`:

| node | model | what |
|---|---|---|
| normalize | Haiku 4.5 | romanized Telugu -> Telugu script |
| route | Haiku 4.5 | kind (story / moral / lookup / out_of_scope), optional work filter from `WORK_PROFILES`, one Telugu search query |
| retrieve | local | top 6 chapter cards: BGE-M3 over card units + char-4gram BM25, RRF-fused (`app/retrieval.py`) |
| grade | Haiku 4.5 | do the chapter summaries contain the answer? else refuse |
| fetch | local | all verses (Telugu script + IAST) of the top 3 chapters, max 120 verses each |
| generate | Sonnet 5 | Telugu answer; each citation = verse id + VERBATIM Telugu-script quote + tatparyam |
| verify | local | quote must be a substring of the cited verse; failed -> one regeneration; zero verified -> refuse |

Verified tatparyams are appended to `corpus/tatparyam_cache.jsonl` as `unreviewed` (lazy translation layer).
Models are overridable with `PURANA_MODEL_FAST` / `PURANA_MODEL_GEN`. Reranking is available in
`retrieval.search(rerank=True)` but off by default (not yet measured).

- Smoke test passed on story / moral / romanized queries: 6–7 verified citations each, 0 dropped.
